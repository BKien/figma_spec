# OCL Utility Semantics

Each utility declaration used by a use case is repeated inside that use case's local PlantUML. This document explains notation; it supplies no missing UML vocabulary.

OCL uses standard primitive types `String`, `Integer`, `Real`, `Boolean`, standard collections and `Tuple`. `Real` denotes exact decimal arithmetic in this specification. `null` denotes an absent optional value; accessing a child of a nullable value requires the preceding guard. Persistent-state comparisons refer to property values at the operation's entry and completion. Precondition failure rejects an operation before any persistence; failure postconditions also cover errors before commit.

`Text::trim` removes surrounding Unicode whitespace. `Text::nfc` returns NFC text. `Text::lower` applies Unicode lowercase. `Text::matches` performs a full regular-expression match; callers use `.*` for contained characters. `Text::email` checks email address syntax. `Text::last4` returns the final four characters of an already accepted number.

`Numeric::finite` rejects NaN and infinities. `Numeric::scale` counts fractional decimal digits after removing insignificant trailing zeros. `Numeric::round2` uses exact decimal HALF_UP rounding to two places. An empty sum is zero. DECIMAL(18,2) bounds are checked before database conversion; extra significant fractional digits are rejected before MySQL can round them.

`CalendarDate` is a Gregorian date value, with `year`, `month` and `ordinal`, the count of calendar-day boundaries from a fixed epoch. Date equality compares the date value. `CalendarDate::parse` accepts only valid YYYY-MM-DD calendar text. `monthStart` and `monthEnd` return the first and last dates of the argument's month. `previousMonth` returns the first date of the immediately preceding month, including the January-to-December year boundary. `ctx.today` is captured once in Asia/Saigon; `ctx.now` is the operation commit timestamp in RFC 3339 UTC form.

`PasswordHasher::matches` verifies bcrypt without returning a hash; `cost` reports its bcrypt work factor. `AccountVault::encrypt` denotes authenticated encryption under an external key; the implementation may randomize ciphertext. Equality to its result means the ciphertext generated by that particular call. `decrypt` returns the original digit sequence. `fingerprint` denotes keyed HMAC-SHA-256 of the exact sequence under an external key. Encryption and HMAC keys are not database columns.

Pagination and recent-activity membership use the number of eligible rows preceding a transaction by date descending and ID descending. Separate sequence constraints establish display order; no ordering of Tuple values is assumed. OCL and PlantUML are specification artifacts; validation of structural closure does not prove formal OCL execution or implementation compliance.

`Text::username` starts with the normalized email's prefix before the @ character; if taken, it appends the first unused positive integer suffix. Database uniqueness resolves concurrent collisions; username generation is retried within registration. Snapshot frame conditions capture every persisted property in a value Tuple and compare pre-state with post-state. They deliberately do not compare persistent object identity alone.

Read-service postconditions describe normal successful returns; protocol errors are exceptional completions rather than a fabricated successful result. Mutation services additionally model an explicit unsuccessful result for rollback constraints. Snapshot comparisons are scoped to the operation's isolated transaction view, so unrelated concurrent commits are not described as changes made by this operation.
